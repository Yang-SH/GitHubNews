## 是什么

DeepSeek 官方开源的统一高性能 tensor core 内核库：把现代大模型的关键计算原语——FP8/FP4/BF16 GEMM、通信重叠的融合 MoE（Mega MoE）、lightning indexer 的 MQA scoring、HyperConnection 等——收进一个 cohesive 的 CUDA 代码库。借鉴 CUTLASS 的部分设计概念，但所有内核通过 DeepJIT 在运行时编译，安装阶段不需要编译 CUDA。MIT 许可，2025-02 创建，撰写时 8.6k Star、1.4k fork、维护活跃。

## 解决什么问题

LLM 推理/训练的 GPU 内核优化是少数专家的领域：手写 CUDA 门槛高，通用库（cuBLAS）对新低精度格式（FP8/FP4）和 MoE 通信融合的支持往往滞后，CUTLASS 模板元编程的学习曲线又陡。DeepGEMM 把 DeepSeek 自家生产环境验证过的内核（支撑其模型训练推理的那套）整理成可直接引入的库，DeepJIT 免掉了安装期编译的部署痛点，让"用上 SOTA 内核"从跟研究论文复现变成一个依赖引入。

## 适用场景

- **自建推理/训练栈的团队**：需要低精度 GEMM 与 MoE 内核，但养不起专职 CUDA 内核团队。
- **MoE 服务优化**：通信重叠的融合 MoE 是其明确能力项，适合做推理吞吐调优时参考或直接引入。
- **内核工程学习**：单一代码库覆盖多种现代原语，是读"生产级内核怎么写"的优质样本。

## 潜在问题与风险

- **维护绑定 DeepSeek 自身需求**：路线图以其内部用例为准，非核心场景的 issue 响应有限（149 个 open issue）。
- **性能强依赖具体硬件与工具链**：不同 GPU 代际、驱动版本表现需自行验证，官方口径未必覆盖你的环境。
- **API 稳定性以其内部用例为准**：作为公司配套开源，不承诺对外 API 长期稳定。
- **使用门槛仍在**：DeepJIT 免去了安装编译，但调优和排错仍需要 CUDA 工程能力。
