## 是什么

给 agent 装上 CAD 能力的插件/技能包：本地工作流生成 STEP/GLB/STL/3MF 三维模型文件，附带面向制造的设计检查（DFM）、工程图纸生成，并可对接主流 3D 打印、钣金与 CNC 加工服务。技术栈是 Python 侧的 cadgen（PyPI 包）+ build123d + Open CASCADE，经 uv 管理，以本地 MCP 服务器（`cadgen mcp`）和 skills 两种形态接入 Claude Code、Codex、Cursor、Gemini、Grok 等支持插件或 skills 框架的 agent。MIT 许可，2026-04 创建，撰写时 1.8 万 Star、维护活跃（快照当日仍有推送）。

## 解决什么问题

参数化 CAD（如 build123d 的代码优先建模）天然适合 agent：模型就是代码，文本→代码→实体是 LLM 擅长的链路，而传统 CAD 的 GUI 操作不是。text-to-cad 把"从建模到可制造性检查再到下单加工"整条链路封装成 agent 可调用的本地工作流，让"描述一个零件→拿到可打印/可加工的文件"成为一次对话。它补上了 agent 工具版图里"比特到原子"的缺环。

## 适用场景

- **硬件原型迭代**：结构件/外壳的快速打样——agent 直接产出可制造的 STEP/STL，对接打印与 CNC 服务。
- **工程师提效**：DFM 检查与工程图纸生成作为设计校验的辅助环节。
- **教学与爱好者**：用自然语言跨过 CAD 软件的学习曲线，直接进入建模。

## 潜在问题与风险

- **可制造性最终要人签字**：DFM 检查是辅助而非保证，公差、材料、装配约束的最终责任在工程师；agent 生成的模型直接送加工前必须人工复核。
- **安装链路较重**：uv 管理的 Python 运行时 + Open CASCADE + Node 侧组件，首次启动需联网下载 CAD 运行时；离线环境接入成本高。
- **项目较新（约半年）**：38 个 open issue，规模尚可但 API 与技能形态可能仍在校准；单一核心维护者的 bus factor 待观察。
- **skills 类工具的通病**：引入即让 agent 执行第三方指令文本与本地代码，敏感环境需先审阅其技能文件与 MCP 暴露面。
