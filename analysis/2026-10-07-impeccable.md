## 是什么

面向 AI 编码工具的前端设计指导体系：1 个 skill、24 个命令（polish/audit/critique/bolder/quieter/distill 等，构成与 agent 沟通设计的共享词汇表）、实时浏览器迭代，以及 **60 条确定性检测规则**——规则由 CLI 和浏览器扩展本地执行，不调 LLM、不要 API key。起点的自我认知很清楚：从 Anthropic 的 frontend-design skill 衍生而来。安装即 `npx impeccable install` + `/impeccable init`，后者把产品定位沉淀为 `PRODUCT.md`（受众、目标、约束、语气），视觉体系另存 `DESIGN.md`。Apache-2.0，2025-11 创建，7.8 万 Star。

## 解决什么问题

所有模型都在同一批 SaaS 模板上训练，跳过设计指导的 AI 前端千篇一律：万物 Inter 字体、紫蓝渐变、卡片套卡片、彩底灰字、标题上方一个圆角方块图标。impeccable 的解法是两层混合：LLM 负责审美判断与迭代，确定性规则负责可机械检验的底线（无 LLM 也能跑）——相当于给 AI 前端引入了"设计版 lint"，把设计质量从纯玄学变成可检测项加可对话项。

## 适用场景

- **AI 生成前端的质检**：用 `/impeccable audit` 与确定性规则给 agent 产出做底线把关，规则本地可跑、适合进 CI。
- **给 agent 建立设计词汇**：24 个命令让"再大胆一点/收敛一点/去繁就简"成为可复现的操作，而非每次重新描述。
- **新产品从零定型**：`init` 强制先回答"产品是什么、给谁用"，再谈视觉——顺序本身就是价值。

## 潜在问题与风险

- **审美立场内嵌**：它对"什么是好的前端设计"有明确观点（反 SaaS 千篇一律），与你的品牌调性冲突时需有取舍；24 个命令的学习与治理成本也不低。
- **规则的天花板**：60 条确定性规则只能覆盖可机械化的维度，真正的设计判断仍在 LLM 侧——别把 `audit` 通过当成设计合格。
- **产品独立性与商业化**：有配套站点 impeccable.style，核心开源但周边走向（托管/付费功能）需持续观察；Apache-2.0 保障了自由使用。
- **skills 类工具的通病**：skill 指令会深度影响 agent 的前端产出风格，团队引入前应审阅其指令内容并小范围试点。
