## 是什么

自然语言驱动的 web/mobile 端到端测试框架：同一个测试文件里，`agent.act('升级到 Pro 套餐')` 这样的自然语言步骤与常规 locator 断言混用。工程形态是 npm 包 `e2e`（SDK + runner + CLI，v0.18.0，Apache-2.0）加一组周边：web 引擎基于 Playwright（Chromium/Firefox/WebKit），mobile 引擎基于 agent-device（iOS 模拟器/Android 模拟器），另有 GitHub PR 评论 reporter、托管浏览器与模拟器等包。模型自带：订阅、API key 或本地模型均可。

## 解决什么问题

E2E 测试的两大顽疾是编写成本高和脆弱（选择器一变就挂）。e2e 的做法是让 agent 用自然语言驱动应用完成复杂流程，把"怎么点"外包给模型。更关键的是一个工程决策：**agent 步骤在首次执行时被记录，后续重放不调用模型，直到应用行为变化**——LLM 的成本与不确定性被限制在录制阶段，重放阶段是确定性的；不含 agent 步骤的测试则完全不碰模型。这直接回应了"AI 测试 = 又贵又飘"的普遍疑虑。

## 适用场景

- **选择器难写的复杂流程**：多步 checkout、订阅升级这类"描述目标比写脚本容易"的场景（README 示例即"invoice 显示按比例金额"的语义断言）。
- **双端 UI 测试**：一套框架同时覆盖 web（Playwright 系）与 iOS/Android（模拟器/真机）。
- **从 Playwright 渐进迁移**：同一测试内混用传统断言与 agent 步骤，不用二选一。

## 潜在问题与风险

- **pre-1.0**：README 明言 API 与配置在 minor 版本间仍会变动，生产引入需锁版本。
- **语义断言的可靠性依赖模型**：`agent.assert` 存在假通过/假失败的可能，关键路径建议叠加确定性断言（框架设计本身就支持混用）。
- **商业引流背景**：由 agentic 测试平台 TesterArmy 开发，README 带较多站外链接；CLI 默认发送匿名遥测（可 `E2E_TELEMETRY_DISABLED=1` 关闭），企业环境注意合规。
- **重放失效的维护成本**：应用一变 agent 步骤就要重录，"变化检测"的粒度决定这套机制的实际省心程度，需在真实项目里观察。
- **活跃度已核实、年龄未核实**：快照当日仍有提交（atom feed 核实，2026-10-06）；仓库创建时间因 GitHub API 配额限制未查，引入前建议补看 star 增长曲线与 issue 响应速度。
