## 是什么

持久记忆压缩系统：自动捕获 agent 会话中的工具使用观察，AI 压缩成语义摘要存入本地记忆库，未来会话按需检索注入，让 agent 对项目的认知跨会话延续。为 Claude Code 构建，同时兼容 Codex、Gemini、Copilot、OpenCode 等多款 agent 工具。架构：5 个生命周期钩子（SessionStart/UserPromptSubmit/PostToolUse/Stop/SessionEnd）+ 本地 worker 服务（HTTP API 与 web 查看器，Bun 管理）+ SQLite 存储 + Chroma 向量库做语义/关键词混合检索；对外暴露 4 个 MCP 检索工具，采用三层渐进披露（search 索引 ~50-100 token/条 → timeline 时间线 → get_observations 全文 ~500-1,000 token/条），宣称约 10 倍 token 节省。Apache-2.0，v13.33.0，Node ≥ 20。

## 解决什么问题

编码 agent 默认每次会话失忆：项目结构、历史决策、踩过的坑全部随会话结束丢失，而完整历史又远超上下文窗口。claude-mem 的答案是"压缩 + 渐进召回"——不追求把一切塞进上下文，而是把做过什么变成可检索的记忆，用三层 MCP 工具按 token 预算逐层取详情。9.7 万 Star 说明"agent 失忆"是当前最普遍的痛点之一。

## 适用场景

- **长周期项目**：跨天/跨周的开发，agent 需要记住此前的决策、修复历史与项目约定。
- **多工具混用**：同一记忆库供多个 agent 工具共享，换工具不换记忆。
- **知识沉淀与回看**：本地 web 查看器让人可以直接浏览 agent 的工作记忆，兼作工作日志。

## 潜在问题与风险

- **隐私边界必须看清**：本地 SQLite 是默认路径，但部分 IDE 安装（如 Grok Bot）**默认走托管版 CMEM Pro**，记忆数据上云，本地观察反而是 opt-in——企业/敏感项目务必显式选择本地模式。
- **"捕获一切"的另一面**：工具使用观察可能包含代码片段、密钥、内部 URL，敏感项目需确认其过滤与清理能力。
- **迭代极快**：主版本号已到 13，快速迭代通常伴随破坏性变更与安装器复杂度（钩子注入 + worker 服务 + 向量库的组合排错成本不低）。
- **压缩质量决定上限**：摘要失真或召回噪声会直接污染 agent 判断，重要决策的记忆建议人工抽查。
- **活跃度已核实、年龄未核实**：快照当日仍有提交（atom feed 核实，2026-10-06）；仓库创建时间因 GitHub API 配额限制未查，v13 的迭代速度说明项目尚处快速演化期。
